# Drama Visual Studio — 角色与场景视觉工作室

一个技能完成从角色设计到生产提示词的整条链：**设计模式**负责从剧本事实推导「这个人是谁、怎么站、长什么样、穿什么」，**变体模式**负责为已有角色设计新造型，**生产模式**负责「设定图、入景、场景变更、扩图、资产链」，**审查模式**负责返图纠偏。默认输出文本，不生成图片；MJ 默认英文，GPT Image 2 沿用用户指定语言或当前请求语言。

新建图像统一走一套高级半写实 3D CG 视觉体系：人物精致风格化，场景自然写实，两者共用同一套渲染基础、光照规律、材质体系、色彩管理和电影级后期。

本文件只做导航和安装说明。**规则以 `SKILL.md` 与 `references/contract/` 为准**，这里不重复。

## 四种模式

| 模式 | 什么时候用 | 交付 |
| --- | --- | --- |
| **设计模式** | 从概念或剧本冲突设计新角色、服装或设定图 | 锁定行 + IFV 三元组 + 7 点中文蓝图 + 3 行对抗性批评 + preflight 与 10 轴批次向量 + 英文提示词 + 排除项 + 可选角色记录 |
| **变体模式** | 给已有角色换装、换发型、加饰品、换场合 | 锁定行（剪影与主色标注为继承）+ 7 点蓝图（身份块逐字沿用记录，第 2 点改写场合）+ Look 四因素分离校验 + 提示词 + 账本 `↳` 行 |
| **生产模式** | 已有设计，要做具体产物 | 简短交接说明 + 一条复制即用提示词 |
| **审查模式** | 收到返图，检查是否偏移 | 观察到的实际差异 + 按需提供的局部修正提示词 |

## 两条贯穿全包的分界

**一、Craft 与 Decision 分开，且每个 Decision 必须过「换人测试（Swap Test）」。**
渲染工艺（眼睑线、虹膜纤维、双高光、瓷面光泽、发丝成束）是 Craft，逐字复用、全组共享；角色特征是 Decision，必须在四个正交维度上从角色事实独立推导。判据：**如果把这个决定原封不动换给同题材的另一个角色，是否依然成立？** 如果成立，说明它是题材套路而非角色推导，必须重推。定义见 `contract/gates.md` §8。

**二、「新角色」和「同一角色的第二套造型」走两套不同的批次规则。**
动笔前先读批次账本（`contract/records.md` §8），判定本次是新角色还是已有角色的变体：

| | 新角色（Mode A / B） | 同一角色的变体（Mode C） |
| --- | --- | --- |
| 剪影 / 主色（轴 1–2） | **必须避开所有已有行**（硬失败） | **默认继承**，不参与全组排他比对 |
| 面部身份集（§1A 骨相 + §1B 表皮） | 从 Position 与注视/言语习惯推导 | **逐字复用角色记录，严禁重推** |
| 正交静态姿态（轴 10） | 重心 · 空手动作 · 视线与相邻角色至少两项不同 | 按新造型场合指定静态姿态 |
| 批次通过判据 | 10 轴中至少 6 轴不同，且非 Craft 词汇重合率 ≤ 28% | 4 个 Look 因素（拓扑、镶边、纹样、节点分布）至少 3 项不同 |
| 账本记录 | 新增 Cast 行 | 记入父角色名下的 `↳` 变体行，不占剪影/主色槽位 |

定义见 `contract/gates.md` §9 与 §9A，流程见 `pipeline/design.md` §1 Mode C。

## 四维正交推导与门禁流程

1. **D1 骨相与体态切割（`engine/02` §1A + `engine/03` §2.1）**：从 Position 三元组推导 10 项骨相参数（优先推开面部指数、口宽、眼距三大锚点），并确定头身比（`7.0–8.5`）及服装视觉腰线与下摆截断比例。
2. **D2 面部表皮与微妆符号（`engine/02` §1B）**：独立推导虹膜光学、眼周重心方向、唇部功能状态、皮肤哑光/高光切面与唯一标记规则（**默认 0 标记**，仅在剧本创伤/仪式要求时允许最多 1 处）。
3. **D3 身体力学与三视图静态姿态（`engine/01` §7 + `pipeline/sheet.md`）**：三视图要求**正交对齐（orthographic alignment）**，但**严禁默认中庸站姿（`neutral balanced stance`）**。每个角色必须明确声明四维姿态向量：`重心轴 · 肩颈线 · 空手服装交互 · 下巴与视线`。
4. **D4 冲突母题、IFV 三元组与审美五算子（`engine/03`）**：
   - 当输入缺少具体场景时，先走 `engine/01` §1 的 **Step 0 薄简报造境**（功法与法则意象 / 气场与高定廓形锁 / 宿命与超凡印记）；
   - 从冲突推导母题种子并回答三条生长法则（支撑物、压力落点、空手行为）；
   - 对照 `atlas/genre-traps.md` 锁定 **`IFV（Invariant 不变量 / Free 自由变量 / Forbidden 题材禁令）`**；
   - 执行 **比例、节奏与留白破律、10% 明暗块（Notan）、冷暖对抗、物理承重与历史形制落地（Grounding）** 五个算子，从 `atlas/lexicon.md` 选取未绑定物理词素，按 `pipeline/design.md` §4 的五段式语法骨架组装英文提示词。
5. **双重门禁（`pipeline/design.md` §6 + `engine/04` §1）**：交付前同时通过 `scripts/preflight.py` 机械计数扫描与 **3 行对抗性批评（最强套路指控 vs 3 个具象物证反驳 + 换人测试结论）**。

## 维护约定

1. **一条规则只有一个家。** 新增或修改全局规则时写进 `contract/`；其他文件只写引用路径与小节号。
2. **IFV 三元组与 7 点蓝图不可省略。** 第 1 点必须包含四维静态姿态向量；第 4 点必须写明承重结构与裁剪比例；第 5 点必须给出层数、描边率（含未处理边集）、带结构职责的节点数、三尺度纹样覆盖与留白呼吸区；第 7 点必须同时写出 `§1A` 骨相数值与 `§1B` 表皮五项推导。
3. **Craft 与 Decision 不能混。** 见上文分界一。
4. **设计不是单角色事件。** 见上文分界二。
5. **双重门禁缺一不可。** `pipeline/design.md` §6 的机械计数通过 `scripts/preflight.py` 校验，对抗性批评（`engine/04` §1）与视觉判断项必须如实写出，不得用脚本通过冒充视觉通过。
6. **不写历史。** 文档只描述当前状态，不记录历史版本差异。变更历史保存在 git 提交中。

## 机械校验

`scripts/preflight.py` 解析英文提示词正文，校验词数预算、颜色与材质词频上限（accent ≤ 2 / anchor ≤ 4 / base ≤ 8 / 单一材质 ≤ 5）、禁用词与裸写中庸站姿、`--no` 规则、6 大固定 Craft 元素、4D 推导锚点（骨相、头身比、表皮光学、四维姿态）、套路 N-gram 陷阱、10 轴批次账本比对，以及跨角色非 Craft 词汇重合率（默认上限 28%），失败返回非零退出码：

```bash
python -I scripts/preflight.py prompt.txt --register editorial
python -I scripts/preflight.py prompt.txt --register glamour --palette
python -I scripts/preflight.py char_b.txt --register editorial --palette \
    --ledger batch.txt \
    --vector "column · 月白+天青 · topology 5 骨相紧束 · editorial gear 2 · dir4/金丝修补寒玉剑冠 · 高调珠光 · 冷银窄压边 · 冰裂剑气几何纹 · 面部指数1.50+霜银琉璃瞳+无印记 · 双足并立+双手拢广袖+平视清冷" \
    --compare-prompt char_a.txt
python -I scripts/preflight.py char_a_ceremony.txt --register glamour \
    --ledger batch.txt --variant-of "A 九幽魔宗左护法" --inherit \
    --vector "topology 1 顶峰下泻 · 暗绯鎏金宽镶边 · 业火红莲暗纹 · 节点聚于乌金高冠与双肩垂链"
```

## 使用示例

- 角色设计：`仙侠 / 魔道九幽 / editorial。设计一位执掌摄魂骨铃的九幽魔宗左护法，昳丽危险，出 16:9 身份三视图设定图。`
- 角色换装（变体模式）：`基于 A 九幽魔宗左护法的角色记录，设计他出席血海祭典时的盛装觉醒造型，走变体模式。`
- 竖屏首帧：`设计一位短剧女主的竖屏首帧，9:16，雨夜，冷光，脸在上三分之一。`
- 次要角色 GPT 设定图：`设计一位仙门世家年轻剑侍，直接给 GPT Image 2 设定图提示词，参考附件重要角色设定图的画风。`
- 场景与变更：`黄昏的悬空仙山楼阁，不要人。` / `基于这张 MJ 底图，给我 GPT Image 2 雨夜版提示词，保留机位与建筑道路结构。`
- 扩图与返图审查：`只补全被裁掉的流光纱披帛和袖口，不扩成全身。` / `对比设定图和这张返图，指出偏移，先只给观察。`
